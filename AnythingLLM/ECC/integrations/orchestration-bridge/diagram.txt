ECC ORCHESTRATION BRIDGE — DIAGRAMA TÉCNICO (A)
================================================
Claude Code = orquestador y verificador. OpenCode = motor de generación.
Antigravity = fallback experimental, apagado por defecto.

Convención: [H]=hook  [S]=script  [P]=policy  [T]=telemetría  (( ))=servicio externo


0. PLANO GENERAL
----------------

   ┌──────────────────────────────── CLAUDE CODE (orquestador) ─────────────────────────────┐
   │                                                                                        │
   │  SessionStart [H] ──► session-start-bootstrap.js                                       │
   │      └─ carga model-route.yaml [P], abre run-ledger.jsonl [T], fija run_id             │
   │                                                                                        │
   │  ┌── ciclo de trabajo ───────────────────────────────────────────────────────────┐     │
   │  │                                                                               │     │

   │  │      · presupuesto: coste_estimado > cost_cap → degrada a modelo barato        │     │

   │  │                                │                                              │     │

   │  │                                                                               │     │

   │  │       nivel 1 — TRIAGE   ► claude-sonnet-5                                    │     │
   │  │            entrada: diff + checklist del PR/issue                             │     │

   │  │                                │                                              │     │
   │  │            needs_deep == false ─┴──► DECISIÓN                                  │     │
   │  │            needs_deep == true                                                  │     │
   │  │                 │                                                              │     │
   │  │       nivel 2 — VALIDACIÓN FINAL ► claude-opus-4-8                            │     │

   │  │                                                                               │     │
   │  │  (6) DECISIÓN                                                                  │     │
   │  │       score >= 0.85 y sin fails  ──► approve      (auto-merge si lo permite)   │     │
   │  │       0.70 <= score < 0.85       ──► auto_fix     (re-run dirigido)            │     │

   │  │       cualquier fail de seguridad──► human_review (ignora el score)            │     │

   └────────────────────────────────────────────────────────────────────────────────────────┘


1. RUTA DE MODELO (resumen ejecutable — la fuente de verdad es model-route.yaml)
--------------------------------------------------------------------------------

   tipo de tarea              motor      modelo primario    fallback
   ─────────────────────────  ─────────  ─────────────────  ─────────────────
   bulk_codegen               opencode   ${OC_MODEL_BULK}   claude-sonnet-5
   refactor_mecanico          opencode   ${OC_MODEL_BULK}   ${OC_MODEL_REFAC}
   scripting / migraciones    opencode   ${OC_MODEL_SCRIPT} claude-sonnet-5
   triage + checklist         claude     claude-sonnet-5    claude-opus-4-8
   review seguridad / final   claude     claude-opus-4-8    (ninguno: humano)
   planificación crítica      claude     claude-fable-5     claude-opus-4-8
   scaffolding experimental   antigravity  n/a              opencode


2. SUPERFICIE DE INVOCACIÓN
---------------------------

   OpenCode
     CLI   : open-code.sh generate --task-type <t> --model <m> --prompt-file <f>
     HTTP  : POST ${ECC_OPENCODE_URL}/v1/generate
             Authorization: Bearer ${ECC_OPENCODE_TOKEN}
             body {task_type, model, prompt, repo_path, timeout_s}
             200  {run_id, diff, files[], exit_code, usage{...}}

   Antigravity  (bloqueado salvo experimental=true)
     HTTP  : POST ${ECC_ANTIGRAVITY_URL}/v1/scaffold
             Authorization: Bearer ${ECC_ANTIGRAVITY_TOKEN}
             X-ECC-Experimental: true      ← el gate lo exige, el servidor lo exige
             body {prompt, sandbox: true, write_scope: "scaffold/**"}

   Claude Code
     interno: enrutado por model-route.yaml; sin endpoint externo.

4. INVARIANTES (si se rompe uno, el bridge está mal desplegado)
---------------------------------------------------------------
   I1  Ninguna llamada a Antigravity sin experimental=true Y ECC_ALLOW_ANTIGRAVITY=1.
   I2  Toda decisión escribe una línea en run-ledger.jsonl con {model, score, decision}.
   I3  score < 0.70  ⇒  decision = human_review. Sin excepción por coste ni por prisa.
   I4  Un fail de seguridad anula el score agregado.
   I5  Los gates deterministas (lint/test/sec) corren antes que cualquier LLM.
   I6  Todo artefacto se registra por sha256 para no re-verificar lo idéntico.
   I7  Los hooks salen con exit 0 ante error propio: el bridge nunca bloquea la sesión.
   I8  OPT-IN: sin activación explícita el bridge no hace nada — ni ledger, ni
       salida, ni efectos. El default es apagado y desactivar es reversible sin
       dejar estado. Única excepción: el gate de PreToolUse, que sólo reacciona
       a invocaciones de open-code.sh (ejecutar el script ya es un opt-in).
   I9  Sin adaptador de verificación no se aprueba nada: se manda a humano.
       Un verificador que aprueba sin verificar es peor que no tenerlo.
